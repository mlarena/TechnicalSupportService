# Ролевая система СУТП

## Обзор

Система управления технической поддержкой (СУТП) использует 4 роли, реализованные на базе ASP.NET Core Identity. Каждый пользователь имеет ровно одну роль, которая определяет его права на просмотр данных и выполнение действий.

---

## Список ролей

| Роль | Идентификатор | Описание |
|------|---------------|----------|
| **Администратор** | `Admin` | Полный доступ ко всем функциям системы |
| **Инженер** | `Engineer` | Работа с назначенными заявками, изменение статусов |
| **Менеджер** | `Manager` | Управление заявками, назначение исполнителей |
| **Заявитель** | `Applicant` | Создание заявок, просмотр только своих заявок |

## Навигация в интерфейсе

### Все авторизованные пользователи видят:
- **Дашборд** — главная страница со статистикой
- **Заявки** — список заявок (с ограничениями по роли)

### Только Администратор видит:
- **Админ** (выпадающее меню):
  - Пользователи
  - Продукты
  - Отделы

### Все авторизованные пользователи имеют доступ к:
- Профиль (просмотр и редактирование своего ФИО, должности, телефона)
- Смена пароля
- Выход из системы

## Изменение статуса заявки

Допустимые переходы статусов определяются текущим статусом заявки и ролью пользователя.

### Таблица допустимых переходов

| Текущий статус | Администратор | Инженер | Менеджер | Заявитель |
|---------------|---------------|---------|----------|-----------|
| **Новая** | → Назначена, Закрыта | — | → Назначена, Закрыта | — |
| **Назначена** | → Закрыта | → В работе | → Закрыта | — |
| **В работе** | → Закрыта | → Решена | → Закрыта | — |
| **Решена** | → Закрыта, Переоткрыта | — | → Закрыта, Переоткрыта | → Закрыта, Переоткрыта |
| **Закрыта** | → Переоткрыта | — | → Переоткрыта | → Переоткрыта |
| **Переоткрыта** | → Закрыта | — | → Закрыта | — |

### Описание переходов

- **Новая → Назначена**: назначается исполнитель (автоматически при выборе из списка)
- **Назначена → В работе**: инженер приступает к работе
- **В работе → Решена**: инженер отмечает заявку как решённую
- **Решена → Закрыта**: заявка закрывается (доступно всем ролям)
- **Решена → Переоткрыта**: заявка возвращается в работу
- **Закрыта → Переоткрыта**: закрытая заявка переоткрывается
- **Переоткрыта → Закрыта**: переоткрытая заявка снова закрывается
- **Любой → Закрыта**: администратор и менеджер могут закрыть заявку из любого состояния

## Техническая реализация

### Роли
Роли хранятся в таблице `AspNetRoles` (Identity). Константы ролей определены в `Core/Constants/Roles.cs`.

### Проверка прав
- На уровне контроллеров: атрибуты `[Authorize]` и `[Authorize(Roles = "...")]`
- На уровне сервисов: проверка роли через `User.FindFirstValue(ClaimTypes.Role)`
- На уровне UI: `User.IsInRole(Roles.Admin)` в Razor-представлениях

### Статусы заявок
Статусы определены в enum `TicketStatus`:
- `New` (Новая) — заявка только что создана
- `Assigned` (Назначена) — назначен исполнитель
- `InProgress` (В работе) — исполнитель работает над заявкой
- `Resolved` (Решена) — исполнитель пометил как решённую
- `Closed` (Закрыта) — заявка закрыта
- `Reopened` (Переоткрыта) — закрытая заявка возвращена в работу

### Валидация переходов
Валидация переходов статусов реализована в двух местах:
1. `TicketsController.GetValidTransitions()` — определяет, какие переходы показывать в UI
2. `TicketService.IsValidTransition()` — серверная валидация при попытке смены статуса
